# 5-seaweedfs — Self-hosted object storage (personal CDN)

Deploys [SeaweedFS](https://github.com/seaweedfs/seaweedfs) (S3-compatible
object storage) as a personal CDN for two use cases:

1. **Sharing clips** with friends via direct, linkable URLs (Discord previews
   the file inline when the URL points straight at it).
2. **Hosting build artifacts** — e.g. the `real-life-soundboard` debug APK — so
   they can be downloaded straight onto a phone for testing.

## What it creates

- A single all-in-one SeaweedFS pod (master, volume, filer and S3 gateway in
  one process) in the `seaweedfs` namespace, on a `local-path` PVC (default
  `30Gi`).
- One bucket per use case (`clips` and `artifacts` by default). Objects are
  anonymously readable at `https://cdn.rutgerpronk.com/<bucket>/<file>`;
  anonymous listing and writes are denied.
- S3 credentials (an admin and a read-only identity), generated by OpenTofu and
  stored in the `seaweedfs-s3-credentials` secret.
- A Traefik `IngressRoute` with a cert-manager certificate for the S3 gateway.
  Nothing else (filer, master, admin UI) is exposed.

## Required CI configuration

| Kind | Name           | Example               |
| ---- | -------------- | --------------------- |
| var  | `CDN_HOSTNAME` | `cdn.rutgerpronk.com` |

The hostname must have a DNS A-record pointing at the Traefik LoadBalancer IP
(`TRAEFIK_IP` from `3-metallb-config`).

## Uploading

Any S3 client works. Get the admin keys from the cluster:

```bash
kubectl -n seaweedfs get secret seaweedfs-s3-credentials -o json \
  | jq -r '.data | map_values(@base64d)'
```

```bash
mcli alias set cdn https://cdn.rutgerpronk.com <admin_access_key_id> <admin_secret_access_key>
mcli cp clip.mp4 cdn/clips/clip.mp4
# -> https://cdn.rutgerpronk.com/clips/clip.mp4
```

## Buckets

Buckets are created by the chart's post-install hook from `bucket_names`. The
hook only creates; removing a name leaves the bucket in place. To expire old
files, the chart supports a per-bucket `ttl` (e.g. `7d`) in `createBuckets`.
